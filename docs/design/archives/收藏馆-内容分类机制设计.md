# 收藏馆：内容分类机制设计

> 配套《收藏+记忆模式设计》：用户收藏进私人博物馆的照片/剪藏/手录，怎么被组织、被找到、被复习、被看见。
> 三条设计前提：
> ① **分类不是为了"整理"，是为了复习与成长**——分类必须反哺 SRS 与馆中馆玩法；
> ② **零负担优先**——用户永远不需要"先建文件夹再收藏"；
> ③ **状态是投影**——学习状态（新入/复习中/已掌握）不由用户管理，只由 SRS 派生。

## 一、三层分类模型

```
馆 Collection（主题域）       例：「我的咖啡学」
  └── 系列 Series（子主题）     例：「拉花 12 式」
        └── 藏品 Item（单卡）    例：拉花 latte art 的照片卡
```

- **三层封顶，不许更深**：深层级 = 整理负担 = 用户流失（独立开发者尤其耗不起）。
- **多标签交叉**：一件藏品可以同时出现在多个馆（如"拉花照"既在咖啡学、也在技能学习），但**主馆唯一**（决定它陈列在哪一格）。
- 馆必须"恰好一个动作搞懂"：馆名=听的懂 + 有画面（咖啡学、我的东京线），系统默认名不好听时引导用户改名一次。

## 二、五个分类维度

| 维度 | 谁管理 | 用途 | 说明 |
| --- | --- | --- | --- |
| 主题（主分类） | AI 打标 + 用户可改 | 馆/系列归属、按馆复习 | 唯一进入三层模型的维度 |
| 语言（副标签） | AI 自动（多语言识别） | 复习过滤（只练日语收藏）、多语言混排 | 日语/英语/其他，可空 |
| 来源（副标签） | 系统自动 | 运营分析、纪念价值展示 | 拍照/剪藏/手录 |
| 时间（滤镜） | 系统自动 | 时间胶囊、月度回顾、成长见证 | 不是分类，是检索滤镜 |
| 状态（投影） | SRS 引擎派生 | 复习队列、蒙尘、待清理箱 | 见第六章，绝不手动管理 |

> 规则：**只有"主题"能被用户编辑**，其余维度全部自动 —— 用户只做"这属于哪？"这一个决定。

## 三、AI 自动打标机制

### 3.1 三层识别管线（离线优先 + 低置信度降级）

```
收藏动作
  │
  ├─ 有文字（剪藏/手录/照片 OCR）→ ① 本地规则打标
  │       关键词命中预设主题词表 → 直接归馆（置信度 90%+）
  │       未命中 → ② LLM 增强打标（在线，批量合并请求）
  │
  └─ 无文字（纯照片）→ 图像标签（端上轻量模型/第三方视觉 API）
  │       得到实体词 → 回到②映射到主题词表
  │
  任一步置信度 < 阈值 → 进入「待归类箱」（见 4.2）
```

### 3.2 预设主题树（初始版本，可随数据扩充）

- 数量策略：**12~16 个一级馆 + 每馆 3~6 个子系列标签**，封顶可控。
- 初始馆清单（覆盖收藏高发域）：

```
饮食（咖啡/茶饮/美食/烘焙）  旅行（日本/东南亚/欧洲/城市）
工作（工具/技能/人脉/会议）   学习（日语/英语/考证/阅读）
居家（收纳/园艺/宠物/烹饪）   兴趣（动漫/游戏/音乐/摄影）
健康（运动/饮食营养/睡眠）    自然（植物/天气/星空）
人物（名字/面孔/纪念）        清单（购物/待办/灵感）
```

- 馆带**图标 + 颜色**（馆徽），游戏化与视觉识别双用。
- 多语言：日语收藏自动标 `语言=ja`，进"日语馆筛选"。

### 3.3 LLM 增强的边界

- 只在"本地规则未命中"时调用（省成本）；结果缓存为"该词 → 馆"映射，下次直接命中。
- 输出强制 JSON：`{language, theme, series, confidence}`，低置信度（<0.6）一律进待归类箱而不是瞎归。

## 四、手动干预与防整理负担

### 4.1 干预手段（只保留三个）

| 动作 | 入口 | 频次预期 |
| --- | --- | --- |
| 改馆/拖拽 | 藏品详情页 / 馆之间拖拽 | ≤ 1 次/藏品 |
| 改名（馆/系列） | 馆页长按 | ≤ 1 次/馆 |
| 合并/拆分 | 系列页 | 低频 |

### 4.2 待归类箱（轻提示，不惩罚）

- 低置信度藏品进「待归类箱」，馆页出现**一等轻提示**（"2 件藏品等你归位"）。
- 一键可"按建议归馆"；不做成大事，不打断主流复习流。
- 超过 14 天未归位的，自动归入「灵感杂货铺」（默认兜底馆，可改名）。

### 4.3 三条防负担铁律

1. **分类永远可以被跳过**：收藏即归馆只是默认；用户不归也照常复习（待在杂货铺）。
2. **一次动作完成分类**：建议一次点击"接受/改到X馆"，不做二级确认。
3. **不鼓励精细管理**：UI 里不出现"标签管理""批量整理"大入口——整理是副作用，不是功能。

## 五、分类驱动的玩法

分类不是冷数据，它给三个系统供血：

| 玩法 | 分类如何驱动 |
| --- | --- |
| **按馆复习** | 复习页可筛选"今日修咖啡馆"（场景化复习：情境线索=情景记忆）；默认仍是大扫除混合队列（交错原则不破） |
| **馆中馆等级** | 每个馆按"藏品数 + 养护完成度"升星；集齐系列点亮馆徽金光（收集驱动） |
| **记忆路线** | 地点类馆自动按地点排序 = 一条 Method of Loci 路线（我的东京线 = 涉谷→新宿→秋叶原，按店回忆） |
| **时间胶囊** | 按月回放"那时的馆进度"（成长见证） |
| **分享名片** | 博物馆名片 = 馆长图鉴（馆徽墙），天然晒点 |

> 关键：**分类 → 复习筛选 → 情景记忆**这条链路是收藏馆相对官方馆的独有价值，UI 上要把"按馆复习"放到显眼位置。

## 六、状态维度：投影原则

```
学习状态（新入 / 复习中 / 已掌握 / 蒙尘 / 待清理）
         = 由 review_log + SRS 派生，实时计算，不可手动改
```

- 状态不是分类，是**滤镜**（类似"只看已掌握的"）。
- 防囤积机制延续：未复习的藏品不进展柜（已在收藏模式文档 6.1）；状态滤镜是它的表达层。
- 好处：用户无法"假装学会"，SRS 数据永不因整理被污染（投影原则，架构铁律不变）。

## 七、数据结构

```sql
-- 馆（主题域）
collections(id, name, icon, color, owner_id, is_default, created_at)
-- 系列（子主题，可空）
series(id, collection_id, name, pos)
-- 藏品（= 一张记忆卡 + 收藏元数据；学习字段仍在 cards 表）
items(
  id, collection_id, series_id, card_id,      -- card_id → 官方 cards 表（SRS）
  source,                  -- photo | clip | manual
  media_url,               -- 照片/截图；剪藏存引用链接
  note,                    -- 用户"为什么收藏它"（一句话）
  tags,                    -- 多标签：["旅行","日本"]（json）
  language,                -- ja | en | null（AI 打标）
  auto_tagged,             -- 是否自动打标（运营分析）
  created_at, reviewed_at
)
-- 多标签交叉：item_tags(item_id, tag)
```

- 三层模型通过外键表达：`items → series → collection`；多标签用 `item_tags`。
- 学习字段仍走 `cards`/`review_log`（架构文档 7.x 不动），**分类纯属 metadata**。
- 离线优先：分类全部存在本地，同步时随日志上传。

## 八、冷启动与验证指标

### 8.1 冷启动（新用户第一天）

```
开局 = 「新手三馆」预置引导：
  咖啡学（示例藏品已就位，教"这是展柜"）
  + 通勤路（拍下今天的地铁站 → 第一次收藏仪式）
  + 宠物/爱好（如果用户选了猫，预置"我的猫"馆）
动作=关键：引导用户完成 1 收藏 + 1 复习 → 进正常循环
```

### 8.2 验证指标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 自动打标准确率（用户不改） | > 80% | 分类负担的第一道闸门 |
| 用户主动改馆率 | < 30% | 高=打标要调 |
| 按馆复习使用率 | > 40% | 分类真的在反哺复习 |
| 待归类箱滞留率（14 天未归） | < 15% | 太少=打标太准没增益；太多=负担 |
| 一周后仍有 ≥1 个自定义馆/改名 | > 50% | "我的馆"资产感建立 |

## 结论

> **分类机制的目标不是让馆藏井然有序，而是让每一件藏品在需要被想起时能回到它所属的情境里。**
> 五维分类里只有"主题"开放给用户，其余全自动；三层模型封顶、待归类箱兜底、状态永远投影——用最小的整理成本，换来"按馆复习 → 情境唤起 → 情景记忆"这条收藏馆独有的记忆链路。
